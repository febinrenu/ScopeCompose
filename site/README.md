# ScopeCompose — project site

The research site for *Beyond Source Selection*. It is two things at once:

- **A scroll story in eleven acts.** A persistent WebGL world (glass, light, a quarter-million
  particles, post-processing) shows the failure and the fix. Two passages collide, selection deletes a true branch, the scope geometry
  explains why, and composition rebuilds the answer.
- **An instrument.** The project's own engines (scope algebra, four-way relation, routing, stage-1
  detector, composition operator, renderer, faithfulness check, textual judge, statistics, retrieval
  baselines) run live in the page. They are JavaScript ports, verified against the Python on every
  build.

Every figure on the page is one of two kinds:

- **Computed** in the browser from the corpus and those engines.
- **Quoted** from a named artifact, with its source shown beside it. These live in
  `src/data/facts.ts`. The decisive experiment is imported straight from
  `benchmark/data/decisive.json`.

Illustrative examples are labelled wherever they appear.

## Run it

**On Windows, double-click `start.bat` in the repository root.** It needs only Node.js ≥ 20.19 (and
offers to install it with winget if it is missing). It then:

1. installs dependencies on the first run;
2. checks the engines against the recorded Python;
3. builds the site;
4. opens it at http://localhost:4173.

Other modes: `start.bat dev` for live reload, `start.bat verify` for the full engine report.

**On macOS or Linux**, run `./start.sh` from the repository root (same steps, same modes). On a Mac
you can also double-click `start.command` in Finder; the first time, macOS may need right-click →
Open, because the file came from the internet.

**On a phone or tablet:** both launchers also serve the site on your local network and print the
address to open, for example `http://192.168.1.5:4173`. The phone must be on the same Wi-Fi.
- The launchers pick a free port first, so the printed links are always the right ones.
- The first time, allow Node.js through the firewall. On Windows, tick Public networks too if
  you're on college or hotel Wi-Fi.
- Networks that keep devices apart need a phone hotspot that the laptop joins.
- `SC_LOCAL_ONLY=1` keeps the server on this computer only.

By hand:

```bash
cd site
npm ci
npm run dev        # http://localhost:5173, with hot reload
npm run build      # -> site/dist
npm run preview    # http://localhost:4173, serves the production build
```

**This site no longer opens from `file://`.** Three.js ships only as ES modules, and browsers block
module scripts on `file://`. Serve it instead:

- `npm run preview` while developing;
- `python -m http.server -d site/dist` for any built copy. This works offline, so for a demo in a room
  with no network, bring the `dist/` folder.

Useful switches, as URL parameters:

| Parameter | Effect |
|---|---|
| `?q=off\|low\|mid\|high` | force a quality tier (`off` = no 3D at all) |
| `?motion=reduce\|full` | override the reduced-motion preference |
| `?still` | freeze time and ignore the pointer: the frame depends on scroll alone (used by the smoke test) |
| `?debug` | frame-time HUD, draw calls, tier, DPR, and a "lose context" button |

## The engines, and why they are checked

The files in `public/engine/` reimplement the Python they name, so the page *computes* its answers
rather than displaying stored ones.

A port can drift, and a page that computes a different relation from the pipeline is worse than a
screenshot, because it still looks authoritative. So four layers guard them:

1. **Port check.** `make_reference.py` records the Python's answers and `verify_engines.js` replays
   them. It covers `compare` on every ordered branch pair, the full `combine` truth table, every
   route, the detector (score, verdict, escalation and all 17 features), textual judging, the oracle
   chain, and the retrieval baselines.
   - Current status: compare 84/84, combine 12/12, route 9/9, detector 128/128, textual 126/126,
     oracle 42/42, retrieval 126/126.
   - `baselines.js` used to exist twice, once inline in the verifier and once in the bench. It now
     exists once and both load it, so the copy that ships is the copy that is checked.
2. **Bytes ship untouched.** The engines are classic scripts in `public/`, which Vite copies verbatim.
   `check_dist.mjs` proves that `dist/` holds byte-identical copies, loaded in the right order before
   the module bundle, and that no bundle contains a second copy of engine code.
3. **One door.** Only `src/engine/bridge.ts` may name an engine global; `tests/bridge.test.ts` fails
   on any other reference. Everything else calls through `engine()` or the adapters in
   `pipeline.ts`.
4. **Adapters match the Python.** `tests/golden.test.ts` replays the reference through the site's own
   orchestration: resolver judgements, rendered oracle answers, retrieval losses and detector
   scores. It also pins the bench's headline numbers, so a data change is a deliberate copy review.
   - It also pins the two instances where the analyser and the gold label genuinely disagree:
     `wp1_fin_imp_019` and `wp1_imm_opp_055`. The page reports them as disagreements.

```bash
python site/tools/make_reference.py && node site/tools/verify_engines.js   # port
cd site && npm test && npm run build && npm run check:dist                 # site
```

## How the story works

**One number drives the world: the story cursor.**

- `acts/keyframes.ts` lists named stops (arrival, retrieval, collision, socket, the four relations,
  engine, demo, composition, research, frontier, closing).
- Each stop is a *complete* set of world parameters: camera rail, blend weights, burn, scope
  geometry and so on.
- `sampleActs(cursor)` interpolates between neighbouring stops. Camera parameters use a Catmull-Rom
  path, and every segment holds briefly at each stop.

**The world is a pure function of the cursor**, so scrolling back lands on the identical frame. The
smoke test checks this: it compares screenshots of one scroll position taken on the way down and on
the way back up.

**Each act's section maps onto its own span of stops** (`cursorFor`). While the section is pinned,
the cursor walks that act's own keyframes. Only as the section scrolls out does the world travel on
to the next act. So a scene never starts turning into the next one while its own copy is still on
screen.

**Lenis is the only smoother.** It feeds ScrollTrigger, and the GSAP ticker drives Lenis and the
render loop together. Some details:

- Pinned acts use `position: sticky`, not pin-spacers.
- Copy within a pinned act is arranged as **beats** that switch on and off as a function of scroll,
  so they are reversible too.
- Below 760px wide the pinned acts become ordinary flowing text: each beat is a frosted card, with
  room between cards to see the world. The world still follows the scroll, and in portrait it
  re-centres on each act's subject.

**Signature moments:**

- **Arrival (Act 00).** A glass sculpture of the mark (the rule's sphere holding the exception's)
  in front of the wordmark drawn in particles. The pointer parts the particles. Dragging turns the
  glass; let go mid-flick and it keeps the momentum, then swings home on a damped spring.
- **Retrieval (Act 01).** One node of light per benchmark instance. A query comet, a BM25 beam and a
  dense beam, and five real corpus passages arriving as cards.
- **The deletion (Act 02).** Two glass monoliths carry the passages. A credibility scan picks one;
  a stillness band holds one amber caret; the exception cracks from its right edge and shatters
  into Voronoi shards (`fracture.ts`: each shard's pose is a function of `burn` and `compose` only).
- **The invisible failure (Act 03).** The kept passage on a pedestal, the empty socket beside it,
  and an x-ray lens (the cursor; it parks on the socket without one) that shows the missing branch.
  The audit computes SR = 0.50 live.
- **The four relations (Act 04).** Two raymarched applicability volumes. They melt together where
  outcomes agree and bruise coral where they disagree. Overlap and disagreement are separate
  parameters, because the project decides them separately. Each tab runs its example through the
  real chain and shows what the engine returned.
- **The engine (Act 05).** A sideways journey past seven station scenes and the contract gate.
- **Try the reasoning (Act 06).** Beside the reader controls, a live tree: question → branches →
  the two answers. Its edges are what the engines returned: which branches selection kept and
  which the composition kept. A marker sits on the branch that is true for the reader. Change the
  reader and the marker moves (GSAP Flip), and the answer that dropped their branch turns coral.

**Portals.** Entering acts 01, 02, 04, 05, 07 and 10, the frame closes to a circle. At the turning
point the screen is the brand mark (the rule's ring holding the exception's), with the next scene
seen through it, and then it opens on that act. It's a function of the cursor (`ui/portal.ts`,
tested), so it plays backwards when you scroll up. It hides the in-between morph, and it's DOM, so
it works at every tier.
- **The recomposition (Act 07).** The same shards fly back into the exception's place inside the
  rule's region. The composed answer and its citations come from `renderTemplate()`.

**Real data in the world:**

- The constellation has one node per corpus instance, and the five cards are real corpus passages.
- The frontier's bars are the stage-1 detector's real scores, one per instance, plotted against both
  thresholds.

**Type.** Four OFL families, self-hosted from @fontsource (`src/styles/type.css`):

| Family | Role |
|---|---|
| Hubot Sans | headlines and titles; its width axis gives condensed, heavy headlines |
| Mona Sans | running text and the big figures; Hubot's sister family, with a plain zero |
| Newsreader | the italic accent and quotations; optical sizes, so headline italics get the display cut |
| Martian Mono | data, labels and code, set semi-condensed |

The 3D textures draw with the same families.

**Legibility rules the world keeps.** There is no small text in 3D. Text drawn into the world is
oversampled, colour-managed and set on a dark backing. Only glowing things exceed 1.0 in linear
light, so bloom never touches type. Chromatic aberration is zero at rest. Depth of field focuses on
whatever carries text. Projected labels hide rather than overlap copy, using layout boxes, so the
answer doesn't depend on a transition in progress.

## Quality tiers, performance, accessibility

`env/tier.ts::classifyTier` maps what the device reports to a tier, and is tested on real renderer
strings:

| Tier | When | What runs |
|---|---|---|
| 0 | software GL, no WebGL2, Save-Data | no 3D chunk at all; a CSS poster stands in |
| 1 | weak GPU / ≤4 cores / ≤4 GB | DPR 1, 16k particles, fake glass, no post-processing, render only on change |
| 2 | default | DPR ≤1.5, 65k particles, transmission glass, bloom + lens, ambient at 30 fps |
| 3 | strong GPU | DPR ≤1.75, 262k particles, depth of field, MSAA at DPR ≤1.25, ambient at 60 fps |

**Governor.** Every 120 frames it checks the 90th-percentile frame time. Above 24 ms it steps down,
one rung at a time, and never back up:

1. DPR 1.
2. Depth of field off, half the particles.
3. A quarter of the particles, 24 raymarch steps.

It stays off under `?still`, where the frame must depend on scroll alone.

**Context loss.** Losing the WebGL context shows the poster (`html.gl-lost`), and the world rebuilds
when the context is restored. A second loss keeps the poster for the rest of the session.

**When the world stops drawing:** offscreen behind the colophon, on lab routes, and in background
tabs.

**Reduced motion** (OS setting, or `?motion=reduce`):

- no Lenis, no pinning, no camera flight and no drift;
- every beat is plain visible text;
- the world shows one static frame per stop, dimmed behind the copy.

**Everything essential is DOM text.** In-world labels are DOM elements projected from 3D anchors.
The demo, the relation tabs and the tier toggle are fully keyboard-operable (radiogroup/tablist
semantics, arrow keys). Colour never carries meaning alone: deleted branches are struck through, and
unmeasured figures are hatched.

**Sound** is off by default. It is synthesised (no files), runs only after a click, and is never
needed to understand anything.

**Weight** is enforced by `npm run size` (gzip):

| Bundle | Budget | Size at handoff |
|---|---|---|
| Entry JS | ≤ 100 KB | 90.6 KB |
| Engines + corpus | ≤ 40 KB | 35.3 KB |
| Lazy 3D chunk (Three.js + world) | ≤ 200 KB | 150.9 KB |
| Lazy post-processing chunk (tiers 2–3) | ≤ 90 KB | 75.6 KB |
| CSS | ≤ 15 KB | 12.8 KB |

**Measured on this project's laptop** (RTX 4060 Laptop, headless Chrome on D3D11, 1440×900, DPR 1,
tier 3, `?debug`, scrolling continuously through each act so every frame re-renders):

- frame interval p50 12.8–14.3 ms and p90 15.5–18.8 ms per act, with p99 spikes of 32–66 ms;
- the governor never stepped down;
- 31–38 draw calls per frame (the post chain renders several passes);
- JS heap about 38 MB after a full scroll.

These are rAF intervals, so they show the page holding roughly 60 fps here. They are not per-frame
GPU costs, and they promise nothing on other hardware.

**Lighthouse 12.8** (`vite preview`, local, the same laptop). Runs vary; these are the typical
results of four runs each:

| Run | Performance | Accessibility | Best practices | FCP | LCP | TBT | CLS |
|---|---|---|---|---|---|---|---|
| Desktop | 82–86 | 100 | 100 | 0.5 s | 0.6–0.7 s | 280–340 ms | 0.009 |
| Mobile (simulated 4× CPU slowdown) | 61–63 | 100 | 100 | 2.5 s | 2.9–3.1 s | 1.41–1.55 s | 0.006 |

v2 measured 89 and 66. The v3 world is far heavier, so these needed work to get back close:

- Shader programs are warmed for the half-float target the scene actually renders into.
- Shader error checks, which block on the GPU, run only under `?debug`.
- Particle shapes are built in slices that yield to the page.
- One ScrollTrigger refresh at load instead of three.
- Heading splits happen when a beat first plays.
- The frontier's chart lines no longer force a layout.

The mobile blocking time is the honest cost of computing every figure in the page and building the
3D world on a slow CPU. The largest remaining single task is creating the world and drawing its first
frame. Splitting it with extra yields was tried, and it made desktop worse (TTI moved later), so it
was reverted. Building actors only as their act approaches is the next lever.

## Routes

| Route | What it is |
|---|---|
| `#/` | the story, acts 00–10 |
| `#/bench` | five resolvers on one metric, the detector trace, retrieval loss, the order-invariance prover |
| `#/byo` | type two branches and run the composition operator on them |
| `#/architecture` | the system without the cinema: one accessible SVG and the module map |
| `#/studio` | the Studio: the pipeline, running live (below) |

Old anchors (`#relations`, `#claims`, `#corpus`, …) land on the act that now holds that content.

**The bench is the one to show someone.** The answer it gives is not a win:

```
Selection (prior work)             PR 0.542
ScopeCompose, as it actually runs  PR 0.446   routing-level
Full context, both passages        PR 0.855   gameable
ScopeCompose, routing oracle       PR 0.976   ORACLE, upper bound
Gold scoped answer                 PR 0.699   the scorer's ceiling
```

Three framing rules travel with these numbers. They are typed fields on the resolvers in
`src/engine/pipeline.ts`, so a rewrite cannot drop them, and the smoke test checks they render:

- **The oracle column carries an upper-bound badge.** It is fed gold routing *and* gold branches,
  because B1 extraction has no offline path.
- **The as-it-runs column is scored at the routing step,** exactly as `run_decisive` scores the
  pipeline arm, so it never reads gold branch text.
- **Concatenation scoring above gold is a defect in the metric,** shown with answer length beside it.

## The Studio (`#/studio`)

The pipeline, running. Start everything with `start.bat studio` (or `./start.sh studio`). That
starts the Python engine server (`service/`, port 8008) and opens the Studio.

| Tab | What it does |
|---|---|
| Console | Ask a question over a benchmark record, your own documents, or pasted passages. Fourteen stages light up as the server reports them; click any to inspect exactly what it computed. |
| Evaluate | Run the pipeline over a benchmark split while detector precision/recall, preservation per system, routing and the relation confusion matrix fill in. Export CSV or JSON. |
| Documents & audit | Collections of documents (paste text, fetch a URL, or drop .txt/.md/.pdf/.html), chunked into passages. The audit ranks passage pairs that read as a rule and an exception to it. |
| History | Every server run with every event: open it in the console, watch it again, compare two, export the events (JSON) or a standalone report (HTML), and see LLM spend by step. |
| API | The REST API with copyable curl, Python SDK and JavaScript, and a live "try it". Swagger is at `/docs`. |

What the Console's stage inspector shows for each stage:

- **Retrieval:** the BM25, dense and fused rankings.
- **Detection:** the NLI split, the score against the 0.35–0.75 band, and all 17 pair features.
- **Scope:** descriptors, set relation and the four-way relation, against gold.
- **Extraction:** the contrastive questions, and each candidate against the grounding gate.
- **Composition:** the branches kept.
- **Answer:** with its citations.
- **Faithfulness:** a checklist.
- **Baselines:** on the same input.
- **Reader:** who each answer is right for.
- **Score:** preservation against gold.

The dock has the log, a latency waterfall, every LLM call (model, tokens, latency, cache, prompt
and reply), the QueryRecord as each stage fills it, and the raw events.

**Three sources, one event stream.** All three emit `{run_id, seq, t_ms, stage, kind, title,
payload}`, folded by one reducer (`src/studio/model.ts`). That reducer is tested on the server's
own recordings.

- **The engine server** streams a run live over server-sent events.
- **Without a server,** the browser's verified engines run benchmark records. Hybrid retrieval,
  the LLM stages and B1 extraction say they need the server; they are never simulated.
- **Recordings** of real server runs (`public/data/runs/`, written by `python -m service.record`)
  play back on the static site.

**Honesty, in the Studio:**

- **Overrides are always badged.** When stage 1 misses a conflict, the default policy continues
  under an override badge ("oracle: gold label" on benchmark records). As-run answers with the
  general rule alone, which is the failure the project measures.
- **Gold branches are labelled as oracle input.**
- **Every number comes from the run's own events.**

Weight: the Studio is its own lazy chunk (32.8 KB gzip JS + 5.6 KB CSS), budgeted in `npm run size`.

Two more checks, run on demand (they need the real GPU or the engine server, so they are not in CI):

```bash
npm run contrast        # every text run on every act, 3 viewports: WCAG ratio against what is behind it
npm run smoke:studio    # starts python -m service and drives every Studio tab against it
```

## Deploying

CI (`.github/workflows/static.yml`) has three jobs:

- **verify:** the Python reference and corpus are regenerated and diffed, then the engine replay
  runs.
- **build:** type check, tests, production build, `check:dist`, size budgets, smoke test. The built
  `site/dist` is uploaded as the Pages artifact.
- **deploy:** **disabled** (`if: false`).

**The site reproduces unpublished results.** Enabling it makes the corpus, the findings and the
decisive experiment publicly readable. That decision belongs with the supervisor, not a push. To
publish after sign-off:

1. Remove `if: false` from the deploy job.
2. Switch Pages on once: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

## Conventions

- **The engines are untouchable from the build.** They are classic scripts in `public/engine/`, are
  never imported, and are only ever named in `bridge.ts`.
- **Every number has a provenance.** It is computed from the corpus and engines, or quoted in
  `facts.ts` with a `source`. Never typed into the markup.
- **Content first, motion second.** Every figure is computed and written into the DOM before the
  scroll system or the 3D chunk starts. If either fails, the page is still a complete document.
- **The world is a pure function of scroll.** No accumulated state, so every transition is
  reversible.
- **Never lock scrolling.** Lenis is a progressive enhancement and stays off in reduced motion. Inner
  scrollers carry `data-lenis-prevent`.
- **Colour is never the only carrier of meaning.**
